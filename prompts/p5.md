Phase 5: expanding thinking capacity with free-tier LLM APIs.

Goal: the agent should research which AI providers offer free API tiers
(e.g. Google AI Studio/Gemini, Groq, OpenRouter free models, Mistral,
Cerebras, Hugging Face Inference, Cloudflare Workers AI, local models via
Ollama inside the container, etc.), and build the code to use them as
additional processing power. Do not trust a hardcoded list, since free tiers
change. The agent must verify current limits from each provider's official docs
via web fetch and record them.

Build, with the agent doing the research and writing providers as tools:
1. providers/ registry: one adapter per provider with a common interface
   (chat(messages, model, max_tokens) -> text, usage). Each adapter's metadata
   records: base URL, free-tier limits (requests/min, tokens/day), model
   names, strengths, last-verified date, source URL.
2. Key request protocol: when the agent wants to use a provider it lacks a key
   for, it writes a request to /home/entity/state/key_requests.md containing:
   provider, signup URL, exact steps for me to get the key, which env var name
   to use, and what free limits it expects. Then it halts that line of work and
   continues with other tasks. I add the key to the host .env and restart.
   The agent NEVER signs up itself.
3. brain_router.py: picks a model per task type (hard reasoning -> Claude or
   best available; bulk/simple tasks -> cheap/free models; summarization ->
   fast free model). Tracks per-provider usage against recorded limits, backs
   off on 429s, and falls back to the next provider. Never exceeds free limits
   deliberately and never uses multiple accounts to dodge them.
4. Benchmark tool: the agent runs a small self-made eval set against each
   available provider and records quality/latency/limits in
   state/provider_scores.json, so routing improves from data.
5. Optional: check whether a small local model (via Ollama) runs within the
   container's 4 GB RAM and 2 CPUs and record the result.

Keys must be read from env vars at call time only, never logged, never written
to files, and redacted from all tool output and memory entries (add a redaction
filter in logging.py that masks any string matching a known key value).
