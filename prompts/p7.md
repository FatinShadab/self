Phase 7: the wake-up experience. Build a terminal UI (Python, `textual`
preferred, `rich` as fallback) and a session-continuity system, so that every
time the container starts, the agent "wakes up", remembers what it was doing,
thinks, explores, and talks to me live.

=== 1. Session state (persistent, in /home/entity/state/) ===
- sessions.jsonl: one entry per run: session_id, start/end time, end reason
  (clean_shutdown | stop_file | crash | budget_exhausted), iteration count,
  token spend.
- handoff.json: written at the END of every session (and every N iterations
  as a checkpoint, so a crash still leaves a usable handoff). Contents:
    {
      "summary": "plain-language account of what I did this session",
      "discoveries": ["new facts about my environment"],
      "tools_created": ["name: one-line purpose"],
      "failures_and_lessons": ["what went wrong, what I learned"],
      "open_questions": ["things I don't understand yet"],
      "plan": [{"step": "...", "why": "...", "priority": 1-5, "status": "todo"}],
      "pending_human_requests": ["key requests / capability requests awaiting me"],
      "mood_of_run": "short self-assessment: progressing | stuck | exploring"
    }
- journal.md: append-only, human-readable diary entry per session in the
  agent's own voice, so I can read its story over time.
- Keep handoff.json bounded (size cap). Older sessions get compressed into a
  rolling "long_term_summary" field by an LLM call, never silently dropped.

=== 2. Wake-up sequence (runs automatically on container start) ===
Step 1  Boot check: verify the STOP file is absent, state dir is readable,
        budgets are loaded. If handoff.json is corrupt, fall back to the last
        good checkpoint and tell me.
Step 2  Orient: load handoff.json, self_notes.md, map.json, the last 20
        memory entries, and the tool list. Detect what changed since last
        sleep (new files, different uptime, new env vars present or missing,
        new tools, my own edits).
Step 3  Greet and report: the agent writes me a short message in the TUI:
        "I'm awake. Last time I ... My plan was ... Since then I notice ...
        Today I intend to ...". Include any pending requests for me (keys,
        approvals) at the top.
Step 4  Reflect: one LLM call to review the old plan against current
        reality, then revise the plan (keep, drop, reorder, add). Log why.
Step 5  Begin the autonomous loop with the revised plan, narrating every
        step in the TUI.

=== 3. TUI layout ===
Four panes:
- Thoughts/Narration (main, scrolling): the agent's live commentary, one
  line per action in plain language, color-coded by type (explore, create
  tool, error, lesson, request-to-human).
- Plan (right top): the current plan with statuses; updates live.
- Status (right bottom): session id, iteration, tokens used vs budget,
  active model/provider, tools count, uptime, time since last human input.
- Chat input (bottom): I can type to the agent at any time. Messages are
  injected into its next loop iteration as high-priority context. The agent
  must reply in the narration pane. Support slash commands:
    /pause  /resume  /stop (writes STOP file, triggers clean shutdown)
    /plan   (show full plan)    /journal (show last entry)
    /tools  (list tools)        /requests (show pending requests to me)
    /memory <query> (search memory)    /budget (show spend)
    /goal <text> (set a temporary focus; standing goal is unchanged)
Key rules for the chat: the agent should ask me questions when genuinely
blocked, but must not stall: it keeps working on other plan items while
waiting for my answer.

=== 4. Shutdown and crash handling ===
- On /stop, SIGTERM, budget exhaustion, or STOP file: finish the current
  action, write handoff.json, append the journal entry, write the sessions
  entry, then exit cleanly. The shutdown reflection is the agent's last LLM
  call: "what did I do, what did I learn, what do I plan next, what should
  future-me be careful about".
- On unexpected crash: next wake-up detects a session without an end entry,
  reconstructs from the last checkpoint plus actions.jsonl, tells me it
  crashed, and notes the probable cause in its lessons.
- Checkpoint handoff.json every 10 iterations or 5 minutes.

=== 5. Constraints (same rules as Prompt 0 still apply) ===
- Redact secrets in everything shown in the TUI or written to the handoff,
  journal, or memory.
- The agent never claims to remember things that aren't in its state files.
  If something isn't in memory, it says so and re-checks the environment.
- Every claim in a handoff or greeting about the environment should be
  verifiable: store the command or file that supports it. At wake-up, spot-
  check 2-3 facts from map.json to catch drift.
- No autonomous account creation, no host access expansion, no key handling
  outside the env-var rules.

=== 6. Docker integration ===
- Container entrypoint launches the TUI directly. Add `stdin_open: true` and
  `tty: true` to docker-compose.yml and document `docker compose run --rm
  entity` / `docker attach` usage.
- Add a `--headless` flag that runs the same loop with plain-text logging
  (for when I'm not attached), still writing handoffs.
- Wake-up should work identically after `docker compose down` and `up`,
  since all state lives in the ./workspace volume.

Give me a test script that:
1. starts the agent, lets it run ~10 iterations, then I type /stop,
2. shows me handoff.json and the journal entry,
3. restarts it and confirms the greeting references the previous session's

4. kills the container mid-run (docker kill), restarts it, and confirms the
