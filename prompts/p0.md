We are building "SELF": a self-extending AI agent that lives inside a Docker
Linux container and treats that container as its body. Its single standing goal
is to explore its environment, build a model of what it can do there, write and
test its own tools to fill capability gaps, and improve its own thinking
capacity over time.

Host: Windows with WSL2 and Docker. Language: Python 3.12. Primary LLM:
Ollam's API (key from env var OLLAM_API_KEY).

NON-NEGOTIABLE RULES FOR THE BUILD:
1. The container is the security boundary. No --privileged, no docker.sock
   mount, no host network mode, no bind mounts except ./workspace -> /home/SELF.
   Never mount /mnt/c or any Windows path.
2. The agent has root inside the container. Enforce nothing about shell
   commands inside; enforce everything at the container edge.
3. Secrets never enter the container filesystem. They are passed as env vars
   from a host-side .env file (gitignored). Agent code must never print,
   log, or persist key values.
4. The agent must NEVER create accounts, sign up for services, solve CAPTCHAs,
   or evade rate limits (e.g. multiple accounts). When it needs a credential
   it writes a request to the human and waits. and if user provides the api key or the thing it needs everything else from coding should be done by it self for building that feature.
5. Everything is logged to append-only JSONL: actions, tool creation, network
   requests (host + path only, no secrets), LLM calls, token spend.
6. There is a host-side kill switch: `./kill.sh` stops and removes the
   container; a `STOP` file in the workspace makes the agent halt cleanly.
7. Work in phases. After each phase, give me exact commands to run and verify
   it, and wait for my confirmation before the next phase.

Acknowledge these rules, then wait for Phase 1.
