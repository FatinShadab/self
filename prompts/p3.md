Phase 3: self-written tools.

Add a meta-tool create_tool(name, description, code, test_code):
- Saves to /home/entity/tools/<name>/ with tool.py, test_tool.py, meta.json
  (description, JSON schema for args, created_at, version, pass/fail history).
- Runs the test in a subprocess with a timeout. Only registers the tool if the
  test passes. Failures are returned to the agent with the traceback so it can
  fix and retry (max 3 attempts), then it logs the failure as a lesson.
- A critic step: a second LLM call reviews the tool for obvious bugs, secret
  leakage (reading env vars containing KEY/TOKEN/SECRET and emitting them),
  and unbounded loops. Reject if flagged.
- Tools load dynamically at startup and mid-run.
- Tool retrieval: start with keyword search over descriptions; structure the
  code so embedding search can replace it later. Only the top-k relevant tools
  go into the model's context each step.
- Add tools versioning: updating a tool keeps the old version in tools/<name>/history/.

Test it: ask the agent to build a tool that summarizes disk usage, confirm it
is saved, tested, retrieved, and reused in a later run.
